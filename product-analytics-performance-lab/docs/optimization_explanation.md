# Пояснение оптимизации для защиты

## Задача

Нужно рассчитать три базовых показателя по логам приложения:
- количество уникальных пользователей;
- DAU — уникальные пользователи по дням;
- количество уникальных пользователей по типу события.

## Исходный вариант

В первой реализации использовали цикл `for` и обрабатывали каждую запись отдельно. Для каждой строки обновляли множества пользователей, даты и типов событий.

Плюс этого подхода — он наглядный и легко читается. Минус — Python выполняет много небольших операций для каждой строки.

## Гипотеза оптимизации

Гипотеза: если заменить ручной проход по строкам на встроенные операции pandas `groupby()` и `nunique()`, расчёт на достаточно большом DataFrame будет быстрее.

Почему это может помочь:
- `groupby()` группирует данные по столбцу;
- `nunique()` считает уникальные значения внутри групп;
- многие операции pandas реализованы на низком уровне и оптимизированы для табличных вычислений.

## Что изменили

Вместо ручного заполнения словарей и множеств используем:

```python
df.groupby("event_date")["user_id"].nunique()
```

И для событий:

```python
df.groupby("event_type")["user_id"].nunique()
```

## Как убедились, что ничего не сломали

До замера времени сравниваются словари результатов обеих функций. В них должны совпасть:
- число строк;
- число уникальных пользователей;
- DAU по каждой дате;
- число пользователей по каждому событию.

Также есть автоматические тесты на совпадение результатов и удаление дублей.

## Как измеряем

Используем `time.perf_counter()`, делаем несколько повторов и сравниваем медианное время. Коэффициент ускорения — отношение времени первой версии ко времени второй.

Нельзя заранее обещать конкретный коэффициент: он зависит от размера таблицы, оборудования и окружения. Поэтому на защите нужно открыть файл `results/benchmark_results.csv` после собственного запуска и назвать фактически полученные значения.

## Что сказать, если спросят, почему не всегда быстрее

На маленьком датасете разница может быть небольшой или даже отрицательной: у pandas есть накладные расходы на создание групп. Оптимизация становится заметнее на объёмах, где ручная обработка большого количества строк начинает занимать больше времени. Поэтому мы замеряли производительность на отдельном, более крупном наборе событий, а не делали вывод по нескольким десяткам строк.
